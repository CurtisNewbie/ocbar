# AGENTS.md

macOS menubar app (Swift/AppKit, no SwiftUI) that monitors OpenCode sessions across terminals. App code lives in `ocbar/`.

## Build & run
- **Canonical build is `build.sh` at the repo root, not Xcode.** From the repo root:
  ```bash
  ./build.sh                            # swiftc compile -> ocbar/ocbar_bin, bundles ocbar/ocbar.app
  ./build.sh && open ocbar/ocbar.app    # rebuild + launch after code changes
  ```
- Requires Xcode Command Line Tools (`xcode-select --install`). Builds **arm64-only**, target `macos13.0`.
- App is `LSUIElement` (menubar-only, no Dock icon). Notifications permission prompt appears on first run.
- If macOS blocks the app: System Settings → Privacy & Security → Open Anyway.
- Project copy is `ocbar/ocbar.app`; if you also copied to `/Applications`, `cp -R ocbar.app /Applications` again after each rebuild.
- `ocbar_bin` and `ocbar.app` are gitignored build artifacts.

## Adding / editing Swift files
- `build.sh` compiles an **explicit hardcoded file list** in order. A new `.swift` file is silently not compiled until added there (and to `ocbar.xcodeproj/project.pbxproj` to keep Xcode builds working).
- Top-level executable code is only allowed in `main.swift` (Swift rule) — keep it last in the list.
- No tests, no CI, no linter. Verify with a successful `./build.sh`.

## Architecture
- `main.swift` → `AppDelegate` (status item, menu, bubble, UserDefaults config) → `SessionMonitor` (`@MainActor`, owns 2s scan + 0.5s poll timers and `AppState`) → inline HTTP.
- Discovery: reads `~/.local/state/opencode/service.json` (url, pid, version, password) to locate the single shared OpenCode v2 service; authenticates with HTTP Basic auth (username `opencode`, password from that file). `ProcessScanner.swift` is deleted.
- HTTP polling hits the service endpoints: `GET /api/info` (health/identity), `GET /api/session/active` (busy sessions), `GET /api/session?limit=100&order=desc` (session list incl. project directory), and `GET /api/form` / `GET /api/permission/request` scoped by `location[directory]=<dir>` (pending user input).
- Visibility: the 2s scan matches running processes by executable name (`ps -Ao pid=,comm=`, last path component `opencode`, excluding the `service.json` pid) and parses their argv. A session is shown only if a running client is bound to it by exact session id, so client-less orphaned sessions (e.g. blocked on a permission prompt) are ignored.
- A client pid is bound to **exactly** the session it is driving. The primary source is the **live binding published by the ocbar-bridge TUI plugin** (`~/.local/state/ocbar/bindings/<pid>.json`, see below); if a live client pid has no fresh binding file, ocbar falls back to parsing that client's argv (`ps -Ao pid=,args= -ww`, accepting `--session <id>` / `-s <id>` / `--session=<id>` / `-s=<id>`, i.e. a client started with `opencode --session <id>`). Either way the binding is exact pid↔session — there is no directory-level fallback. Sessions are not collapsed per directory — every bound root session is emitted individually.
- **argv alone is only a launch-time snapshot — the bridge plugin is what makes it live.** The v2 TUI can change which session it drives without touching its argv: `/clear`, `/new`, `/sessions` (aliases `/resume`, `/continue`), `ctrl+o`, `<leader>l`, `<leader>1..9` and session tabs all just `route.navigate` inside the process, so argv keeps naming the session the client was launched with. The ocbar-bridge plugin runs inside that same process and republishes the live route every 200ms, so these in-TUI switches now update the binding in real time — in particular a `/clear` followed by a message (which creates a brand-new session B in the same directory) binds to B correctly. (Historical symptom, still reachable only when the plugin is missing/stale: ocbar binds that pid to the stale launch session and drops the session actually being driven at the `guard let pid = sessionIDToPID[id]` check, so the only fix is relaunching the client with an explicit id.)
- **ocbar-bridge TUI plugin** — source `plugin/ocbar-bridge/tui.js`; `build.sh` installs it to `~/.config/opencode/plugins/ocbar-bridge/tui.js`. It runs inside the TUI client process, so `process.pid` there is the terminal client pid. Every 200ms it reads the live route (`ctx.ui.router.current()`) and atomically writes `{version, pid, sessionID, isRoot, directory, updatedAt}` to `~/.local/state/ocbar/bindings/<pid>.json` (temp file + rename, so ocbar never reads a half-written file); on teardown it deletes that file. ocbar's read priority for each live client pid: a fresh binding file (&lt;15s old) wins, and `sessionID: null` in it means the client is not in any session (e.g. parked on the home page after `/clear`) and ocbar does **not** fall back to argv in that case; only a pid with no fresh binding file falls back to argv parsing. Zero dependencies (only `node:fs`/`node:os`); `setup()` uses `setInterval` + a returned cleanup fn (it runs outside a Solid owner).
- The shell helpers that pass an explicit id live in `~/dev/git/stuff/workspace.sh`: `oc [args…]` mints a fresh random `ses_…` id and runs `opencode --session "$sid"`; `occ` runs `opencode --session <newest session id>` (falling back to `opencode --continue`); `oct` creates `~/ocsession/<yyMMdd-HHmmss>-<rand>/`, `cd`s into it and launches a fresh random id there. A bare `opencode` (no `--session`) carries no id in argv, so without the plugin it is never bound (with the plugin it binds once it enters a session). **Since the bridge plugin binds by live route, the id these helpers pass is no longer needed for ocbar visibility** — passing `--session <id>` still matters only when an id must be chosen *before* the session exists (pre-assigning an id for another consumer) or to jump straight to a specific existing id non-interactively; a bare `opencode` binds the same way once it enters a session, and the TUI's `/sessions` covers resuming interactively. These helpers are the maintainer's **personal** shell functions — nothing ships them — so keep them out of README: other readers don't have them. README should only ever say `opencode --session <id>`.
- Note on the plumbing: OpenCode v2.1.0's **server** exposes **no** client↔session mapping (no client registry, no presence/attach endpoint, `/environment` and `/inbox` are empty; `session.viewed` is only an idle-ack watermark), so the pid↔session link has to come from the **client side**. That client-side publisher now exists — it is the ocbar-bridge plugin above, which reports each client's live session from inside its process; argv parsing is kept only as the fallback for clients without the plugin. The alternatives (accepting client-less busy sessions, or rebinding a pid by directory) were both tried and removed earlier for producing stale sibling rows; see git `ff2dea0`.
- **`OpenCodeClient.swift` is currently dead code** — nothing references it; `SessionMonitor` inlines its own HTTP calls. Don't extend it expecting it to be wired in.
- **Context-window usage** (off by default; shown on the dropdown's detail row and, when on, as the island row's third line) is filled by `SessionMonitor.fillContext` and carried as `SessionInfo.context` (`SessionContext{used, limit, fraction}`, `Models.swift`); it is gated on `UserDefaults` keys `ocbar.contextUsage` (master, default false), `ocbar.contextUsageDisplay` (`percent`|`tokens`|`both`, default `both`), `ocbar.contextUsageWarn` (default 80) and `ocbar.contextUsageCritical` (default 95), all menu-driven in `contextUsageMenu()`. When on: the ceiling comes from `GET /api/model` (`limit.input`/`limit.context`/`limit.output`, TTL-cached 300s) through a copy of opencode's own `usable()` rule (`packages/opencode/src/session/overflow.ts`: `mx = min(output ?? 32000, 32000)`, `usable = input ? input - min(20000, mx) : context - mx`; 46/110 models have no `limit.input`), and the usage from `GET /api/session/<id>/message?limit=10`, taking the first entry with `type == "assistant"` **and** a `tokens` object, because the list is newest-first and the in-flight turn carries no `tokens`. `used = input + output + cache.read + cache.write` — `reasoning` is deliberately excluded and `input` excludes cache, so the prompt is `input + cache.read + cache.write`. `Session.Info.tokens` in the session list is **cumulative** and must not be used for this. Per-session refresh is throttled to 2s. The dropdown row is an indented, non-actionable item whose leading badge image is the session row's own glyph width (`contextDetailItem(for:)`), which is what aligns its text under the session name; `contextDetailExtraInset` is the tuning knob.
- **`IslandPanel.swift`** — the "灵动岛"/notch island, a third surface alongside the menubar item and the bubble. A borderless, non-activating `NSPanel` at `NSWindow.Level(mainMenuWindow + 2)`, top-anchored, **one panel per attached screen**: `IslandHost` keeps one `IslandPanel` per `NSScreen.screens`, rebuilding the set on `didChangeScreenParametersNotification` — only a change to the *set* of displays rebuilds, and a removed display's panel is `retire()`d. On a screen with a notch the panel is anchored to the **cutout**, not to screen centre (`auxiliaryTopLeftArea`/`auxiliaryTopRightArea` for its width, `safeAreaInsets.top` for its height); with no cutout, a top-centred stand-in capsule. The alert is deliberately **not** replayed onto a newly attached display — a rebuild retires the old panels, which folds them. Collapsed it is a black capsule whose two flanks are **the same width**: 130pt each, so a 445pt capsule for a 185pt cutout, cutout centred. Symmetry, not either side's content, sets that width: `islandFlank` = `CollapsedContentView.flankWidth` = `max(requiredLeftFlankWidth, requiredRightFlankWidth)`, used for **both** sides — the right is **130** (three two-digit glyph+count badges + two `groupGap`s + clearance), the left **43** (ring 12 + `groupGap` 6 + that slot's two-digit count 18.57 + clearance), so the right still binds and the capsule does not move when the left changes. **Launch geometry** (the window's x comes from it) and a strict upper bound: `place` trims an overrun *silently*, drawing a two-digit count as `1`; hence two digits on the right, and symmetry at 108 is rejected. **Left flank: a status light, then a bare count:** a hollow ring (`IslandActivityView`), 12pt on a 32pt pill, orange and turning while any session runs, the *same ring* dim neutral (`restingTint`, white α0.40) and still when none is — **never hidden** (a blank wing beside a full one reads as something missing, not as a state). Then the number of sessions working, **with no glyph** — the ring *is* that slot's glyph, so `symbol(for:)` returns `nil` for `.busy` — and counts are white everywhere, colour here living on glyphs. The ring is **12pt so its outer edge lands on a badge glyph's ink** (11pt SF Symbols, ink **12.00 × 12.00pt** in a 14pt box, `widestGlyphWidth`); stroke `max(2.0, 0.14 × diameter)`; the gap stays 90° at every size, leaving **3.0 stroke widths** of opening at 12pt — the floor at which a gap reads as an opening, so a smaller ring needs a *wider* gap, never a lower stroke. **Tint** and **motion** both carry "running", either alone sufficing, because Reduce Motion deletes the motion. Only `counts[.busy] > 0` tints it, and its size never changes with state, so a running↔quiet transition moves nothing. The left flank is **pinned** (`FlankAlignment.pinned(inset:)`) at `leftContentInset` = **47** while the right is centred: only the left has an always-present element whose position is a landmark, and centring the *actual* content was rejected as it drags the ring sideways on every busy↔idle transition. The offset follows `leftContentWidth`: **47 in both states**. **Right flank: the tally** — one badge per remaining state with sessions, most urgent first: `rightBadgeOrder` = `[.error, .waiting, .idle]` = `attentionRanked`'s ranking minus `runningStatus`, carrying the same priority the card sorts its rows by. `badgeStatuses` (`[runningStatus] + rightBadgeOrder`) is the one place all four states are listed, so neither flank can forget a state; three slots draw a tinted glyph plus a count through one construction (one point size, one gap, tabular digits), the running one the count alone. `IslandMarkerGroup` decides glyph and count visibility **separately** (a zero count is what makes a badge not exist) and has **no second marker kind**. One dictionary, `CollapsedContentView.counts`, is the pill's only input: the counts and the status light both derive from it — nothing is ever dropped — so the ring cannot turn while the running count is absent, or vice versa. On a cutout-less display the stand-in capsule is `min(max(screenWidth × 0.14, 160), 240)` **floored by what it must hold** (`standInCapsuleMinWidth` = **172**: the ring + three badges + the bare two-digit count + gaps + clearance) — a floor only ever on top of the fraction, since the share alone is narrower than the block and `place` would trim the last count silently. **`islandLabelWidth(for:)` is the only way an island label's width may be derived from its own text** (`max(intrinsicContentSize, cell.cellSize(forBounds:))`): the bare advance shaves a count's trailing digit (a real bug here), the cell clipping a couple of points inside its frame. Every label whose width comes from its own text calls it (the flank widths, the number's frame, `twoDigitCountWidth`, the row's age); labels the *layout* sizes truncate inside their own rect and are immune. **It is the app's one running mark, not just the pill's**: `IslandRing` is the single source of its geometry and tints; its shape is built once, in `IslandRing.arcPath`, which the live view strokes **and** `IslandRing.image(pointSize:angle:)` renders into an `NSImage` for the two surfaces that cannot host a view (the menubar title's attachment, the dropdown rows' item images). Four surfaces, four diameters, one measurement each: the pill (12, `diameterCap`), a card row (`IslandRowView.ringDiameter` — the check-circle's **ink** at the row's 13pt semibold in its 15pt glyph box: 13.125, so a running row matches the rows beside it), the menubar title (12.000 at 11pt) and a dropdown row (14.000 at 13pt); the last two keep the **canvas contract** — the check-circle's image box, which the title attachment and the detail row are laid out against. Every live mark subscribes to `IslandRingTicker`, the island's **one** 0.06s tick source, so several busy rows plus the pill cost one timer, not one per row; the menubar keeps its own (it drives `NSImage` swaps `AppDelegate` owns) and shares only its *phase*. `IslandRing.angle(at:)` is a pure function of the clock, so every ring is at the same angle at the same instant and a late tick cannot drift one from the others. **Motion is 18° per 0.06s tick (300°/s, one revolution in 1.2s, clockwise) everywhere**, menubar and dropdown included: the old 45°/tick existed for that mark's *shape*: a filled disc with a wedge knocked out has a low-contrast moving part, so 300°/s barely registered on it, while the ring's 90° gap is a large high-contrast discontinuity that at 750°/s reads as a warning blink. The ring is deliberately not a *filled disc*: that is what every badge glyph is, and a filled disc beside one would be a badge that lost its number. **Gates, all in `IslandActivityView.shouldPlay`:** something running; `!NSWorkspace.shared.accessibilityDisplayShouldReduceMotion` (the ring is then held at `restingAngle` — gap centred on 12 o'clock, so a still mark reads as deliberate — and re-read on `NSWorkspace.accessibilityDisplayOptionsDidChangeNotification`, which the menubar's and dropdown's marks honour too, `updateRunningMark` stopping its own timer rather than repainting a still image); and `onScreen`, set by `present()`/`hide()` for the pill and by `IslandPanel.rowsOnScreen` (`visible && expandedState`) for a card row. **There is no timer while nothing is running**: created when a mark starts playing, torn down when it stops, each tick re-checking the same gate. Hover grows the pill into a rounded card **500pt** wide (`islandExpandedCardTargetWidth`, sized so it truncates none of the real session titles; bounded to `0.8 × screen width`, floored at the collapsed capsule) — sized by its *titles*, so widening it to restore an older ratio would only add black. It lists each session as **up to three stacked lines — folder name + right-aligned age / title / context usage — never two fields on one line**, each absent line collapsing the row: `islandRowHeight(lines:)` = `30 + 14 × (lines − 1)`, one source of truth for the card's layout, the height budget and the window frame. **The card's top inset differs by state and only the expanded side may move**: collapsed `rowInset` 8; expanded `topInset` (the cutout height) or 8, **plus `islandExpandedTopPadding` 8**, because the first row is the only one abutting chrome: on a notched display its frame would otherwise start at the cutout's bottom edge with only its text clear of it. The collapsed 8 must **not** move with it: on a cutout-less display 8 being *smaller* than the stand-in capsule's 24pt is what puts the collapsed rows inside the collapsed rect, which is what `hoverLatched` reasons about. The list is **capped by a height budget, not a row count** (`IslandListBudget`): height = `contentTop` + the rows' own heights + `actionRowHeight` + `bottomPadding`, plus `summaryRowHeight` when folded; the row budget is the smaller of 40% of the usable height and the distance to the bottom of the usable area less that chrome, so chrome never costs a visible row. The tail folds into an inert `+k more` row; folding is safe only because the list is re-ranked `error < waiting < busy < idle` (stably, in `attentionRanked`) with the first row always taken, so a fold can never hide an error behind an idle row. `IslandCardView.hitTest` hands clicks only to session rows and — while an alert is armed — to the `Hide` button in its own frame; the summary is inert. Context usage cannot drift from the dropdown: thresholds, wording, display mode and banding are resolved once in `Models.swift` (`ContextUsagePresentation`, `ContextBand`, `ContextDisplayMode`, `compactTokens`) and consumed by both `contextDetailItem` and `AppDelegate.islandContext`. A non-positive model `limit` must be treated as unknown rather than divided by (it once trapped on a divide by zero). A row click is answered by the **host**: `onRowActivated` → `IslandHost.rowActivated`, which folds **every** screen's island first, then calls `onSelectSession(pid)` → `SessionMonitor.focusSession`. **The island is also the reminder surface, and the alert is its only *unprompted* expansion.** `AppDelegate.showBubble` routes the bubble's two transitions here when the bubble is off and the island is on: `IslandHost.alert(name:kind:pid:seconds:)` (`IslandAlertKind.waiting`/`.ready`) opens the card on **every** screen's panel, marks the transitioning session's row with a 3pt rule in the row's leading padding, and folds it after `seconds` (= `ocbar.bubbleSeconds`). It is a rule, not a wash: the row's hover wash *is* the pointer's own affordance (a mark would read as hovered from elsewhere), and tinting the ground would raise an all-alpha row's every tone. The pid is **held** and re-applied on every `update`, because the alert arrives *before* the rows that contain it (the transition precedes the render tick that supplies them), so the mark lands on the row it means; a nil or folded pid marks nothing. `name` is the session's folder display name, the key exit 3 matches on. **While an alert is armed the alert's own timer owns the fold** (`alertWork` — deliberately not `expandWork`/`collapseWork`, which `cancelPending` clears on every expansion): `scheduleCollapse` must refuse to *schedule* one at all (the 0.15s poll would otherwise fold the card ~0.35s after it opened), and `alert()` must also cancel a fold **already booked**, which that guard alone cannot reach. Re-arming replaces the deadline rather than stacking, and re-arming on the *same* row still pops — its spring is keyed on a monotonic generation, so a poll tick cannot restart it. Reduce Motion takes only the pop, never the rule — the rule *is* the information. An alert ends in exactly one place, `clearAlert()`: its own timer, `collapse()` (the menubar, a row click, or the `Hide` button — all the user answering), and `hide()` (no rows, or a retired display). **Three exits, and exactly two of them latch.** (1) The card's only button, `Hide`, every number from this card (`IslandCardButton`): 11pt regular (the age/context/`+k more` size) at white α0.55 → α0.7 on hover, over a resting ground of **half the card's own hover wash** (α0.045 = `islandHoverWashAlpha / 2`) returning to the wash itself (α0.09, the row's own fill, inset 3/2, radius 7) in 0.15s — half a hovered row, never brighter. It sits on an **action row that exists only while an alert is armed** (a hover-opened card needs no way out — leaving already folds it) of the card's own short-row height `summaryRowHeight` (24), so it is chrome in `IslandListBudget` like the folded row; it is its own `hitTest` target (`acceptsFirstMouse`, press swallowed, release-inside activates); its one action is the shared dismissal **without** `focusSession`. (2) A row click — the same dismissal *plus* focus. Both go through `collapse()`: in both the pointer is inside the island by construction, and the latch is what stops the poll re-opening what the user just closed: **`IslandPanel.collapse()` latches the hover open off until the pointer leaves** (`hoverLatched`), without which the next 0.15s tick re-expands the card 0.35s later. It is released only by the pointer being *seen* outside the hover rect, and by anything else opening the card (an alert is new information, not the poll second-guessing a dismissal); `hide` and `present` clear it too. The poll is a `.default`-mode timer AppKit does not service during menu tracking, and it must not become `.common`. (3) The **retract**, which deliberately does *not* latch: `SessionMonitor.onDismiss` → `AppDelegate.dismissReminders` (beside `bubble.dismiss`, same folder display name) → `IslandHost.dismissAlert(named:)` → per-panel `retractAlert(named:)`, firing only where the armed alert's name matches, and ending it as the *timer* does (`endAlert` = `clearAlert()` + `evaluateHover`): the card goes back to the hover machine, so an unattended card folds on the ordinary deadline while one being pointed at stays up. The pointer can be anywhere here, which is why this exit must not latch — merging it into `collapse()` loses a behaviour either way. Three non-obvious requirements, each a real bug here: (1) **hover is polled**, a 0.15s `NSEvent.mouseLocation` check against the *target* rect — **not** `NSTrackingArea`, whose `.inVisibleRect` area the window-resize animation tears down and rebuilds, synthesising enter/exit pairs while the pointer never moves (it oscillated the island forever); (2) the expand/collapse delays are **one-shot** and must be guarded (`expandWork == nil` / `collapseWork == nil`) — the poll re-runs every 0.15s, so a naive cancel-and-reschedule pushes the 0.35s deadline back every tick and it never expands or collapses at all; (3) the panel **must be keyable** (`canBecomeKey` true, `canBecomeMain` false) and every hit-testable view must return `acceptsFirstMouse == true` — a non-keyable non-activating panel of an inactive accessory app gets no mouse events at all, so the pill click, the row click and the `Hide` button are silently dead while hover still works (it only reads the cursor). `AppDelegate.render` pushes `[IslandRow]` on every poll tick, fanning one list to every screen's panel — the push hops to the main actor (`Task { @MainActor in }`) because `render` is nonisolated while the host and panels are `@MainActor`; `menuWillOpen` calls the host's `collapse()`, collapsing **all** of them; menu → "Show island" (`ocbar.island`, default on) toggles them, and with no rows (or disabled) every panel is out.
- busy → idle/waiting transitions drive notifications + speech bubble. App targets OpenCode v2 only: all sessions share one `opencode serve --service` process, so no per-terminal `--port` is needed. v1 users should use tag `oc_v1`. The bubble is gated on `UserDefaults` key `ocbar.bubble` (default true, menu → "Show bubble"); `bounceIcon()` rides with it, since the bounce only exists to point at the bubble. With the bubble off the **island** carries those same two moments instead (`island.alert`, see the `IslandPanel.swift` bullet above), so the reminder is a chain — the bubble, else the island, else nothing beyond `SessionMonitor`'s own system notification — and not two independent switches. The alert sound (`ocbar.alertSound`, default `off`) belongs to neither surface: it rings whenever one of them is about to show something.
- Only root sessions (top-level, not subagent children) that are active/waiting, or already viewed with the later of last view/activity within 30 min, are shown, labeled by project folder name. Menubar shows per-session labels up to a cap (default 4, configurable 0–10 via menu → "Projects shown", UserDefaults key `ocbar.projectsShown`); at 0 it drops project names entirely and renders one glyph + count per status instead (`aggregateTitle`), most urgent first, with the running mark (the ring — see the island bullet) still turning — **unless the island is on**, in which case the menubar drops to the plain `ocbar` name (`MenubarTitleShape.appName`) because the island already carries that detail; the VoiceOver summary keeps the counts on both paths (`aggregateSummary(statuses:)`). The shape is decided by the pure `menubarTitleShape(sessionCount:projectsShown:islandEnabled:)`, delimited by `<menubar-title-shape>` sentinel comments because an out-of-tree harness extracts exactly that block — don't delete the markers as stray comments. With no sessions the item stays the grey dot + "No OpenCode sessions" whatever the toggles say, since the island is ordered out when it has no rows.
