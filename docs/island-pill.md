# The collapsed pill

The pill's two flanks, the numbers that size them, and the app's one running mark — drawn on four surfaces from a single source.

**Two flanks, the same width.** `islandFlank` = `CollapsedContentView.flankWidth` = `max(requiredLeftFlankWidth, requiredRightFlankWidth)`, used for **both** sides, so the capsule is symmetric about the notch by construction: 130pt each, a 445pt capsule for a 185pt cutout, cutout centred. Right **130** (three two-digit glyph+count badges + two `groupGap`s + clearance), left **123** (ring 12 + `groupGap` 6 + two-digit count 18.57 + the CPU readout's own gap and provision, below) — the right binds, so the capsule does not move when the left changes. This is **launch geometry** (the window's x comes from it) and a strict upper bound: `place` trims an overrun *silently*, drawing a two-digit count as `1`; hence two digits on the right, and symmetry at the smaller width (both wings 108) is rejected.

**Left flank: a status light, then a bare count.** A hollow ring (`IslandActivityView`), 12pt on a 32pt pill, orange and turning while any session runs, the *same ring* dim neutral (`restingTint`, white α0.40) and still when none is — **never hidden** (a blank wing beside a full one reads as missing, not as a state). Then the number of sessions working, **with no glyph** — the ring *is* that slot's glyph, so `symbol(for:)` returns `nil` for `.busy` — and counts are white everywhere: colour here lives on glyphs. The ring is **12pt so its outer edge lands on a badge glyph's ink** (11pt SF Symbols, ink **12.00 × 12.00pt** in a 14pt box, `widestGlyphWidth`); stroke `max(2.0, 0.14 × diameter)`; gap 90° at every size, leaving **3.0 stroke widths** of opening at 12pt — the floor at which a gap reads as an opening, so a smaller ring needs a *wider* gap, never a lower stroke. **Tint** and **motion** both carry "running" and either alone suffices, because Reduce Motion deletes the motion; only `counts[.busy] > 0` tints it, and its size never changes with state, so a running↔quiet transition moves nothing.

**The left flank is pinned** (`FlankAlignment.pinned(inset:)`) at `leftContentInset` = **7** while the right is centred: only the left has an always-present element whose position is a landmark, and centring the *actual* content was rejected as it drags the ring sideways on every busy↔idle transition. The offset follows `leftContentWidth`: 7 with the CPU readout provisioned, **47** with it off — constant in every *state* either way.

**The server-CPU readout is the left flank's second pinned element**, `CPU · 1.6%` at **9.5pt** medium tabular — and it is the one setting on the pill: **`CPUUnit`**, picked in `Server CPU → Percent of machine / Percent of one core` (stored under `ocbar.cpuUnit`, **default `machine`**), decides what its percentage is a percentage *of*. The sampler publishes **one** number, the server tree's share of **one core** (`0…999`), and this enum is the only place that converts it: `machine` divides by `activeProcessorCount` and draws **one decimal** (`CPU · 1.6%`, cap `100.0`), `core` draws the share itself as a **whole number** (`CPU · 16%`, cap `999`). One decimal on the machine scale is what keeps a mostly-idle server visible as `0.3%` rather than as a `0` that reads as a rounding error; the core scale runs to three digits, so it already has that resolution, and a decimal there (`999.0%`) would measure wider than the machine's `100.0%` and so widen the flank — a display change the pill may not make. The prefix **ships over the design advice against it** — `CPU` costs 24.6pt of ink to label a 29.0pt value, nearly as much as the value itself, and it is the widest word on the flank at this size; that argument is recorded here as rejected, not forgotten. `·` is U+00B7 with one space either side, and the whole string is one run with one tint: a dimmer prefix would need an attributed string for a distinction nobody reads. `%` is still not optional — the flank already carries bare counts, so an unsuffixed `1.6` would be one more of them. No glyph: colour does not live on a number, and the left flank has one mark, the ring. The decimal separator is always `.` — `String(format:)` with no locale, so a machine set to a decimal comma still draws `1.6%`: a `,` next to the `·` separator would be two marks doing the same job, and the pill's numbers are not a formatting preference. The two units are only ever formats and two derived numbers: nothing else on the pill changes with the pick.

- **Geometry.** `leftContentWidth` 36.565 → **116.714** (`cpuGap` **8** — not `groupGap` 6, which means "same group" — plus a **72.150** provision), so `requiredLeftFlankWidth` 43 → **123** and `leftContentInset` 47 → **7**, `cpuReadoutInset` **52**. Both wings stay 130 and the capsule 445, because the right's 130 still binds (measured 123.0 against 130.0, not estimated): the numbers all moved, the frame did not. The 123 leaves only **7pt** of headroom, down from 16 — the decimal cost the left flank 9pt, and a fourth digit, a larger font or a longer word would now make it the binder. The 72.150 is a provision for **both** `CPUUnit`s, not for one of them, so switching the unit moves none of these numbers.
- **Provisioned at the wider unit's ceiling, never at a typical value.** The provision is the max of `CPU · 100.0%` (72.150, machine) and `CPU · 999%` (62.737, core) — machine wins, so the pill is exactly the size it was before the pick existed. `place` trims an overrun *silently*: a provision at the common `CPU · 1.6%` (59.605) would zero the gap, clamp the leading edge (moving the ring, which is the headroom's whole point) and then `masksToBounds` would draw `CPU · 100.0%` as `CPU · 10`, because the `%` lives in the string's last 12.5pt. Each value is clamped to its unit's cap before it reaches the label for the same reason — `100.0` machine (every logical core busy) or `999` one-core (three digits, the sampler's own clamp), never a four-digit allowance, so the pill cannot draw a percentage the hardware cannot produce.
- **A second pinned inset rather than a third item in the ring+count block**: the readout is always present while its gate is on, so it is a landmark of its own, and hitching it to the count would slide it 18.57pt every time a session started or stopped. `flankWidth` is the element answering for what it *draws*, so it is 0 while unknown — the provision lives in `cpuReadoutWidth`.
- **Unknown draws nothing; `0.0%` is a reading.** A first sample has no baseline, the pid would not report, or the gap since the last tick exceeded three of them (6s — a wake from sleep otherwise renders a fake peak). Every failure re-baselines, or the next good tick bills the whole outage to the process. The readout must never reach the ring: `activity.running` stays `counts[.busy] > 0`, because a tree using half a core — `5.0%` of this machine, `50%` of a core — with every session idle is a busy process, not a session working.
- **Attention is ink, not colour:** `white α0.50`, and `α0.92` (the counts' white) from `CPUUnit.attentionThreshold` — **half a core in whichever unit is drawn**: `5.0%` machine (`50 / cores`, so 6.25 on an 8-core Mac) or `50%` one-core. That is the same statement the first version made with `50` one-core percent, and the ink therefore still starts where it always did. A fixed machine percent that "reads as busy" was rejected — 10 is a tenth of a core on an 8-core Mac and a quarter of one here, so one number would mark two different amounts of work. Threshold and tint are both decided from the value actually drawn, so text and colour cannot be about different numbers; a displayed value only moves when the target is `CPUUnit.deadband` away — **3 one-core points**, i.e. `3` on the core scale and `0.3` on the machine scale (where one point is 10 one-core points on this 10-core box) — the same rule the old **3** always followed, or the EMA's drift would rewrite the digit every tick. The label sits **on the count's baseline, not in a box of its own.** The readout and the count beside it are handed the same region rect (`place`), so `IslandCPUView.layout()` derives where the count's baseline falls from the height alone — `IslandMarkerGroup.countBaseline(atHeight:)`: the **14pt** count line box centred in that height, plus the 11pt ascent (**10.635**) — and drops its own frame by the 9.5pt ascent (**9.185**) to meet it, a single line being drawn with its baseline one ascent below the top of its frame. That replaced a **0.1875pt** raise (an eye-anchor measured at 9pt as 0.25, scaled by **0.75** = (11 − 9.5)/(11 − 9)) which still left the readout **0.64pt** high: two labels centred independently can only align their boxes' middles, and these boxes are **14pt** and **12pt**, so no centre is a shared line. Nothing is kept as a residual nudge and nothing should be: the derivation is font metrics and the pill's height, so it is independent of the string — a nil reading hides the label and moves neither baseline. The mark's **0.5** drop (`pillMarkDrop`, below) is a different question and stays: a stroked ring beside solid digits, not two baselines.
- **The setting costs no geometry.** `IslandCPUView.widestWidth` is the **max over both units' widest strings** — machine's `CPU · 100.0%` (**72.150pt**) against core's `CPU · 999%` (**62.737pt**) — so the provision, the insets, the flanks and the capsule are exactly what they were before the pick existed, and the 7pt of left-flank headroom stays 7. A unit whose format outgrew 72.150pt would have to widen the pill, so the core unit draws no decimal (above) — the alternative was a display change.
- **The pick repaints on its own tick.** The pill is handed the same one-core `Double` every 2s, so its value's equality guard would swallow a unit-only change; the unit therefore rides with that push (`IslandHost.update(…, cpuUnit:)`) and `IslandCPUView.unit`'s setter drops the drawn value and reapplies it in the new unit. Without that, the readout would keep the old unit's string until the next sample — the one visible way this setting could look broken.

Sampling lives in `SessionMonitor` (`ServiceCPUSampler`, see [`session-monitoring.md`](session-monitoring.md)): one `proc_pidinfo` per pid of the server **tree** (server + the descendants it spawned) per scan tick, `Δcpu / Δmach_absolute_time` — both are `mach_absolute_time` units, so the ratio needs no timebase conversion — smoothed by an asymmetric EMA (**0.6** rise, **0.2** fall) and clamped to **0…999 one-core percent** *before* it enters the smoother. The unit is the display's business: nothing in the sampler divides by the core count, and `CPUUnit` is what does when the machine unit is drawn.

**Right flank: the tally** — one badge per remaining state with sessions, most urgent first: `rightBadgeOrder` = `[.error, .waiting, .idle]` = `attentionRanked`'s ranking minus `runningStatus`, carrying the same priority the card sorts its rows by. `badgeStatuses` (`[runningStatus] + rightBadgeOrder`) is the one place all four states are listed, so neither flank can forget a state; three slots draw a tinted glyph plus a count through one construction (one point size, one gap, tabular digits), the running one the count alone. `IslandMarkerGroup` decides glyph and count visibility **separately** (a zero count is what makes a badge not exist) and has **no second marker kind**. One dictionary, `CollapsedContentView.counts`, is the pill's only input **for the counts**: the counts and the status light both derive from it, nothing is ever dropped, and the ring cannot turn while the running count is absent, or vice versa. The server-CPU `cpu` (a **one-core** percentage, `0…999`, with its `cpuUnit` beside it) is the second input and the only other one — it feeds its own element and nothing else, which is what keeps the ring a statement about sessions.

**The stand-in capsule**, on a cutout-less display, is `min(max(screenWidth × 0.14, 160), 240)` **floored by what it must hold** (`standInCapsuleMinWidth` = **258**: the ring + three badges + the bare two-digit count + the CPU readout at its provisioned width + gaps + clearance) — a floor only ever on top of the fraction, since the share alone is narrower than the block and `place` would trim the last count silently. **258 is above the 240 cap, so on a cutout-less display the floor now decides everywhere and the screen share no longer varies**: that is a real consequence, not an oversight — the readout's provision is what pushed it over, and the alternative was a stand-in that draws a different, prefix-less string from the notched pill on the same screen. The readout is counted in the floor **even when its gate is off**: 8pt of tail air costs nothing, and a floor that moved with the gate would need a rebuilt window for no visible gain. Its **shape is the notched pill's**, not a stadium: flat top and rounded bottom, no border ([`island.md`](island.md) owns that rule) — only its width and its 24pt height differ, because it has no cutout to fill.

**`islandLabelWidth(for:)` is the only way an island label's width may be derived from its own text** (`max(intrinsicContentSize, cell.cellSize(forBounds:))`): the bare advance shaves a count's trailing digit (a real bug here), the cell clipping a couple of points inside its frame. Every label whose width comes from its own text calls it (the flank widths, the number's frame, `twoDigitCountWidth`, the row's age); labels the *layout* sizes are immune.

**It is the app's one running mark, not just the pill's.** `IslandRing` is the single source of its geometry and tints; its shape is built once, in `IslandRing.arcPath`, which the live view strokes **and** `IslandRing.image(pointSize:angle:)` renders into an `NSImage` for the two surfaces that cannot host a view (the menubar title's attachment, the dropdown rows' item images). Four surfaces, four diameters, one measurement each: the pill (12, `diameterCap`), a card row (`IslandRowView.ringDiameter` — the check-circle's **ink** at the row's 13pt semibold in its 15pt glyph box: 13.125, so a running row matches the rows beside it), the menubar title (12.000 at 11pt) and a dropdown row (14.000 at 13pt); the last two keep the **canvas contract** — the check-circle's image box, which the title attachment and the detail row are laid out against. Only the card row also shows a session's running subagents as a count in line 1's right slot (orange, `IslandRowView.tallyLabel`); the mark itself carries nothing on any surface — see [`island.md`](island.md).

**The pill's mark alone is dropped 0.5pt** (`IslandActivityView.pillMarkDrop`). Every mark is geometrically centred, but a hollow stroke beside solid digits does not *read* centred: on the cutout-less 24pt capsule the pill's ring looked a hair high against its count, and 2pt overshot it — 0.5 is the eye's number. A card row takes none of it (`markDiameter` is what tells the hosts apart) because a row's mark is centred in a fixed glyph column against the row's other discs, where the geometry and the eye already agree, and the menubar/dropdown images keep their canvas contract.

Every live mark subscribes to **`IslandRingTicker`**, the island's **one** 0.06s tick source, so several busy rows plus the pill cost one timer, not one per row; the menubar keeps its own (it drives `NSImage` swaps `AppDelegate` owns) and shares only its *phase*. `IslandRing.angle(at:)` is a pure function of the clock, so every ring is at the same angle at the same instant and a late tick cannot drift one from the others.

**Motion is 18° per 0.06s tick (300°/s, one revolution in 1.2s, clockwise) everywhere**, menubar and dropdown included: the old 45°/tick existed for that mark's *shape*, a filled disc with a wedge knocked out having a low-contrast moving part that 300°/s barely registered on, while the ring's 90° gap is a large high-contrast discontinuity that at 750°/s reads as a warning blink. The ring is deliberately not a *filled disc* — that is what every badge glyph is, and a filled disc beside one would be a badge that lost its number.

**Gates, all in `IslandActivityView.shouldPlay`:** something running; `!NSWorkspace.shared.accessibilityDisplayShouldReduceMotion` (the ring is then held at `restingAngle`, gap centred on 12 o'clock so a still mark reads as deliberate, and re-read on `NSWorkspace.accessibilityDisplayOptionsDidChangeNotification`, which the menubar's and dropdown's marks honour too, `updateRunningMark` stopping its own timer rather than repainting a still image); and `onScreen`, set by `present()`/`hide()` for the pill and by `rowsOnScreen` (`visible && expandedState`) for a card row. **There is no timer while nothing is running**: created when a mark plays, torn down when it stops, each tick re-checking the same gate.
