# The collapsed pill

The pill's two flanks, the numbers that size them, and the app's one running mark — drawn on four surfaces from a single source.

**Two flanks, the same width.** `islandFlank` = `CollapsedContentView.flankWidth` = `max(requiredLeftFlankWidth, requiredRightFlankWidth)`, used for **both** sides, so the capsule is symmetric about the notch by construction: 130pt each, a 445pt capsule for a 185pt cutout, cutout centred. Right **130** (three two-digit glyph+count badges + two `groupGap`s + clearance), left **114** (ring 12 + `groupGap` 6 + two-digit count 18.57 + the CPU readout's own gap and provision, below) — the right binds, so the capsule does not move when the left changes. This is **launch geometry** (the window's x comes from it) and a strict upper bound: `place` trims an overrun *silently*, drawing a two-digit count as `1`; hence two digits on the right, and symmetry at the smaller width (both wings 108) is rejected.

**Left flank: a status light, then a bare count.** A hollow ring (`IslandActivityView`), 12pt on a 32pt pill, orange and turning while any session runs, the *same ring* dim neutral (`restingTint`, white α0.40) and still when none is — **never hidden** (a blank wing beside a full one reads as missing, not as a state). Then the number of sessions working, **with no glyph** — the ring *is* that slot's glyph, so `symbol(for:)` returns `nil` for `.busy` — and counts are white everywhere: colour here lives on glyphs. The ring is **12pt so its outer edge lands on a badge glyph's ink** (11pt SF Symbols, ink **12.00 × 12.00pt** in a 14pt box, `widestGlyphWidth`); stroke `max(2.0, 0.14 × diameter)`; gap 90° at every size, leaving **3.0 stroke widths** of opening at 12pt — the floor at which a gap reads as an opening, so a smaller ring needs a *wider* gap, never a lower stroke. **Tint** and **motion** both carry "running" and either alone suffices, because Reduce Motion deletes the motion; only `counts[.busy] > 0` tints it, and its size never changes with state, so a running↔quiet transition moves nothing.

**The left flank is pinned** (`FlankAlignment.pinned(inset:)`) at `leftContentInset` = **11** while the right is centred: only the left has an always-present element whose position is a landmark, and centring the *actual* content was rejected as it drags the ring sideways on every busy↔idle transition. The offset follows `leftContentWidth`: 11 with the CPU readout provisioned, **47** with it off — constant in every *state* either way.

**The server-CPU readout is the left flank's second pinned element**, `CPU · 16%` at **9.5pt** medium tabular. The prefix **ships over the design advice against it** — `CPU` costs 18.8pt of ink to label a value narrower than itself, and it is the widest thing on the flank at this size; that argument is recorded here as rejected, not forgotten. `·` is U+00B7 with one space either side, and the whole string is one run with one tint: a dimmer prefix would need an attributed string for a distinction nobody reads. `%` is still not optional — the flank already carries bare counts, so an unsuffixed `16` would be one more of them. No glyph: colour does not live on a number, and the left flank has one mark, the ring.

- **Geometry.** `leftContentWidth` 36.565 → **107.301** (`cpuGap` **8** — not `groupGap` 6, which means "same group" — plus a **62.737** provision), so `requiredLeftFlankWidth` 43 → **114** and `leftContentInset` 47 → **11**. Both wings stay 130 and the capsule 445, because the right's 130 still binds: the numbers all moved, the frame did not. The 114 leaves only **16pt** of headroom — the left is no longer comfortably the narrow side, and a fourth digit, a larger font or a longer word would make it the binder.
- **Provisioned at `CPU · 999%`, never at the typical value.** `place` trims an overrun *silently*: a two-digit provision would zero the gap, clamp the leading edge (moving the ring, which is the headroom's whole point) and then `masksToBounds` would draw `CPU · 100%` as `CPU · 10`. The value is clamped to 999 before it reaches the label for the same reason.
- **A second pinned inset, `cpuReadoutInset` = 56**, rather than a third item in the ring+count block: the readout is always present while its gate is on, so it is a landmark of its own, and hitching it to the count would slide it 18.57pt every time a session started or stopped. `flankWidth` is the element answering for what it *draws*, so it is 0 while unknown — the provision lives in `cpuReadoutWidth`.
- **Unknown draws nothing; `0%` is a reading.** A first sample has no baseline, the pid would not report, or the gap since the last tick exceeded three of them (6s — a wake from sleep otherwise renders a fake peak). Every failure re-baselines, or the next good tick bills the whole outage to the process. The readout must never reach the ring: `activity.running` stays `counts[.busy] > 0`, because a server at 80% with every session idle is a busy process, not a session working.
- **Attention is ink, not colour:** `white α0.50`, and `α0.92` (the counts' white) from **50%**. Threshold and tint are both decided from the integer actually drawn, so text and colour cannot be about different numbers; a displayed value only moves when the target is **3** away, or the EMA's drift rewrites the digits every few ticks. The label sits **0.1875pt** above its box's centre — the same class of correction as the mark's 0.5 drop, opposite sign. **That number is scaled, not derived:** the 9pt anchor was 0.25, and the 9pt-vs-11pt cap-band delta shrinks by exactly **0.75** (= (11 − 9.5)/(11 − 9)) at 9.5pt, so 0.25 × 0.75. Re-deriving it from font metrics alone gives ≈0.05 — a different anchor the eye was never measured against, so do not "fix" it that way without looking at the pill.

Sampling lives in `SessionMonitor` (`ServiceCPUSampler`, see [`session-monitoring.md`](session-monitoring.md)): one `proc_pidinfo` per scan tick, `Δcpu / Δmach_absolute_time` — both are `mach_absolute_time` units, so the ratio needs no timebase conversion — smoothed by an asymmetric EMA (**0.6** rise, **0.2** fall) and clamped to 0…999 *before* it enters it.

**Right flank: the tally** — one badge per remaining state with sessions, most urgent first: `rightBadgeOrder` = `[.error, .waiting, .idle]` = `attentionRanked`'s ranking minus `runningStatus`, carrying the same priority the card sorts its rows by. `badgeStatuses` (`[runningStatus] + rightBadgeOrder`) is the one place all four states are listed, so neither flank can forget a state; three slots draw a tinted glyph plus a count through one construction (one point size, one gap, tabular digits), the running one the count alone. `IslandMarkerGroup` decides glyph and count visibility **separately** (a zero count is what makes a badge not exist) and has **no second marker kind**. One dictionary, `CollapsedContentView.counts`, is the pill's only input **for the counts**: the counts and the status light both derive from it, nothing is ever dropped, and the ring cannot turn while the running count is absent, or vice versa. The server-CPU `cpu` is the second input and the only other one — it feeds its own element and nothing else, which is what keeps the ring a statement about sessions.

**The stand-in capsule**, on a cutout-less display, is `min(max(screenWidth × 0.14, 160), 240)` **floored by what it must hold** (`standInCapsuleMinWidth` = **249**: the ring + three badges + the bare two-digit count + the `CPU · 999%` readout + gaps + clearance) — a floor only ever on top of the fraction, since the share alone is narrower than the block and `place` would trim the last count silently. **249 is above the 240 cap, so on a cutout-less display the floor now decides everywhere and the screen share no longer varies**: that is a real consequence, not an oversight — the readout's provision is what pushed it over, and the alternative was a stand-in that draws a different, prefix-less string from the notched pill on the same screen. The readout is counted in the floor **even when its gate is off**: 8pt of tail air costs nothing, and a floor that moved with the gate would need a rebuilt window for no visible gain. Its **shape is the notched pill's**, not a stadium: flat top and rounded bottom, no border ([`island.md`](island.md) owns that rule) — only its width and its 24pt height differ, because it has no cutout to fill.

**`islandLabelWidth(for:)` is the only way an island label's width may be derived from its own text** (`max(intrinsicContentSize, cell.cellSize(forBounds:))`): the bare advance shaves a count's trailing digit (a real bug here), the cell clipping a couple of points inside its frame. Every label whose width comes from its own text calls it (the flank widths, the number's frame, `twoDigitCountWidth`, the row's age); labels the *layout* sizes are immune.

**It is the app's one running mark, not just the pill's.** `IslandRing` is the single source of its geometry and tints; its shape is built once, in `IslandRing.arcPath`, which the live view strokes **and** `IslandRing.image(pointSize:angle:)` renders into an `NSImage` for the two surfaces that cannot host a view (the menubar title's attachment, the dropdown rows' item images). Four surfaces, four diameters, one measurement each: the pill (12, `diameterCap`), a card row (`IslandRowView.ringDiameter` — the check-circle's **ink** at the row's 13pt semibold in its 15pt glyph box: 13.125, so a running row matches the rows beside it), the menubar title (12.000 at 11pt) and a dropdown row (14.000 at 13pt); the last two keep the **canvas contract** — the check-circle's image box, which the title attachment and the detail row are laid out against. Only the card row also shows a session's running subagents as a count in line 1's right slot (orange, `IslandRowView.tallyLabel`); the mark itself carries nothing on any surface — see [`island.md`](island.md).

**The pill's mark alone is dropped 0.5pt** (`IslandActivityView.pillMarkDrop`). Every mark is geometrically centred, but a hollow stroke beside solid digits does not *read* centred: on the cutout-less 24pt capsule the pill's ring looked a hair high against its count, and 2pt overshot it — 0.5 is the eye's number. A card row takes none of it (`markDiameter` is what tells the hosts apart) because a row's mark is centred in a fixed glyph column against the row's other discs, where the geometry and the eye already agree, and the menubar/dropdown images keep their canvas contract.

Every live mark subscribes to **`IslandRingTicker`**, the island's **one** 0.06s tick source, so several busy rows plus the pill cost one timer, not one per row; the menubar keeps its own (it drives `NSImage` swaps `AppDelegate` owns) and shares only its *phase*. `IslandRing.angle(at:)` is a pure function of the clock, so every ring is at the same angle at the same instant and a late tick cannot drift one from the others.

**Motion is 18° per 0.06s tick (300°/s, one revolution in 1.2s, clockwise) everywhere**, menubar and dropdown included: the old 45°/tick existed for that mark's *shape*, a filled disc with a wedge knocked out having a low-contrast moving part that 300°/s barely registered on, while the ring's 90° gap is a large high-contrast discontinuity that at 750°/s reads as a warning blink. The ring is deliberately not a *filled disc* — that is what every badge glyph is, and a filled disc beside one would be a badge that lost its number.

**Gates, all in `IslandActivityView.shouldPlay`:** something running; `!NSWorkspace.shared.accessibilityDisplayShouldReduceMotion` (the ring is then held at `restingAngle`, gap centred on 12 o'clock so a still mark reads as deliberate, and re-read on `NSWorkspace.accessibilityDisplayOptionsDidChangeNotification`, which the menubar's and dropdown's marks honour too, `updateRunningMark` stopping its own timer rather than repainting a still image); and `onScreen`, set by `present()`/`hide()` for the pill and by `rowsOnScreen` (`visible && expandedState`) for a card row. **There is no timer while nothing is running**: created when a mark plays, torn down when it stops, each tick re-checking the same gate.
