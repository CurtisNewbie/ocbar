# The alert

The island's unprompted expansion: what opens the card by itself, what owns the fold while it is open, and the three ways it ends.

**The island is the reminder surface whenever the bubble is off.** `AppDelegate.showBubble` routes the bubble's two transitions here: `IslandHost.alert(name:kind:pid:seconds:)` (`IslandAlertKind.waiting`/`.ready`) opens the card on **every** screen's panel, marks the transitioning session's row with a 3pt rule in the row's leading padding, and folds it after `seconds` (= `ocbar.bubbleSeconds`). The mark is a rule and not a wash: the row's hover wash *is* the pointer's own affordance (a mark would read as hovered from elsewhere), and tinting the ground would raise an all-alpha row's every tone.

**The pid is held** and re-applied on every `update`, because the alert arrives *before* the rows that contain it (the transition precedes the render tick that supplies them), so the mark lands on the row it means; a nil or folded pid marks nothing. `name` is the session's folder display name, the key the retract matches on.

**While an alert is armed the alert's own timer owns the fold** (`alertWork` — deliberately not `expandWork`/`collapseWork`, which `cancelPending` clears on every expansion): `scheduleCollapse` must refuse to *schedule* one at all (the 0.15s poll would otherwise fold the card ~0.35s after it opened), and `alert()` must also cancel a fold **already booked**, which that guard alone cannot reach. Re-arming replaces the deadline rather than stacking, and re-arming on the *same* row still pops — its spring is keyed on a monotonic generation, so a poll tick cannot restart it. Reduce Motion takes only the pop, never the rule: the rule *is* the information. **An alert ends in exactly one place, `clearAlert()`**: its own timer, `collapse()` (the menubar, a row click, or the `Hide` button — all the user answering), and `hide()` (no rows, or a retired display).

**Three exits, and exactly two of them latch.** (1) The card's only button, `Hide` (`IslandCardButton`): 11pt regular (the age/context/`+k more` size) at white α0.55 → α0.7 on hover, over a resting ground of **half the card's own hover wash** (α0.045 = `islandHoverWashAlpha / 2`) returning to the wash (α0.09, the row's own fill, inset 3/2, radius 7) in 0.15s — half a hovered row, never brighter. Its **action row exists only while an alert is armed** (a hover-opened card needs no way out: leaving already folds it) and is the card's short-row height `summaryRowHeight` (24), so it is chrome in `IslandListBudget` like the folded row ([`island.md`](island.md)); it is its own `hitTest` target (`acceptsFirstMouse`, press swallowed, release-inside activates), and its one action is the shared dismissal **without** `focusSession`. (2) A row click — the same dismissal *plus* focus, wired host-side in [`island.md`](island.md). Both go through `collapse()`: in both the pointer is inside the island by construction, and the latch is what stops the poll re-opening what the user just closed. **`IslandPanel.collapse()` latches the hover open off until the pointer leaves** (`hoverLatched`), without which the next 0.15s tick re-expands the card 0.35s later; released only by the pointer being *seen* outside the hover rect, or by anything else opening the card (an alert is new information, not the poll second-guessing a dismissal); `hide` and `present` clear it. The hover poll is a `.default`-mode timer AppKit does not service during menu tracking, and must not become `.common`. (3) The **retract**, which deliberately does *not* latch: `SessionMonitor.onDismiss` → `AppDelegate.dismissReminders` (beside `bubble.dismiss`, same folder display name) → `IslandHost.dismissAlert(named:)` → per-panel `retractAlert(named:)`, firing only where the armed alert's name matches, and ending it as the *timer* does (`endAlert` = `clearAlert()` + `evaluateHover`): the card goes back to the hover machine, so an unattended card folds on the ordinary deadline while one being pointed at stays up. The pointer can be anywhere here, which is why this exit must not latch: merging it into `collapse()` loses a behaviour either way.
